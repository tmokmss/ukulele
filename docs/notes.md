# ウクレレ コードチェンジ練習アプリ: これまでの議論まとめ

`ukulele-chord-trainer.html` (単一HTMLのPoC) を引き継ぐためのメモ。

## 経緯

- ウクレレ初心者で、いまはコードの押さえ方とコードチェンジを練習している段階
- 最初は楽譜アプリを作る案だったが、コード譜は既存サービス (U-フレット、楽器.me) で足りるのでやめた
- 代わりに「コードチェンジトレーナー」を作ることにした。理由は、いまの段階で一番効く練習がこれで、ちょうどいい既存アプリが少ないから
- そこから「録音してFFTで採点できそう」という話になり、全部入りのPoCを1ファイルで作った

## 練習方法として話したこと (アプリの要件のもと)

- 2つのコードを選び、1分間で何回切り替えられるか数えて記録する
- メトロノームで遅く (BPM60くらい)、4拍ごとにチェンジ。速さより止まらないこと
- 右手の基本ストロークを先に固める
- 早めに3〜4コードの曲を1曲通す
- 毎日10分の方が週末1時間より効く

## 採点の設計

| 項目 | 方法 |
|---|---|
| チェンジのタイミング | 音の立ち上がり (オンセット) を検出し、メトロノームの拍とのズレをmsで出す。実装が一番楽で練習効果も高い |
| コードが合っているか | FFTを12音階に畳んだクロマグラムを、コードのテンプレートとコサイン類似度で照合。コードは倍音が重なるので、ピーク検出より音階ごとのエネルギー比較が安定する |
| ミュートした弦 | 鳴るはずの構成音のエネルギーが弱いと検出。D (2220) のように同じ音名が2本の弦にあると、どちらの弦かは区別できない |

ハマりどころとして出た点:

- 周波数分解能。最低音 C4 (約262Hz) と隣の半音の差は約15Hz。fftSize 4096 だとギリギリなので大きくする
- `getUserMedia` の echoCancellation、noiseSuppression、autoGainControl は全部オフ。オンだと楽器音が加工されて検出が壊れる
- 単音のピッチ検出をやるなら、生のFFTより自己相関やYINの方が精度が出る

## PoCの実装 (ukulele-chord-trainer.html)

音の流れ: `マイク or テスト音 → inputBus → aBig (FFT 16384) / aSmall (FFT 1024)`。クリック音は解析に入れず直接出力。時刻はすべて `AudioContext.currentTime` 基準。

- **ストローク検出** (`detectOnset`): 小さいFFTの 240〜1300Hz のスペクトルフラックス。適応しきい値 + 感度設定、不応期110ms
- **クリック音の回り込み対策**: クリックは 2000/2600Hz にして検出帯域の外に置いた
- **タイミング採点**: 検出時刻から補正値を引き、最も近い拍とのズレを出す。拍の ±30% (最大250ms) の外は裏拍として無視。50ms以内がジャスト、110ms以内が早め/遅め
- **コード判定** (`computeChroma`, `scoreChords`): ピークを拾って放物線補間、クロマに集計。640Hz以上は倍音対策で重みを下げる。16コードと照合
- **集計区間**: 前のコードの残響とFFT窓 (約340ms) を避けるため、チェンジ後0.32秒から次のチェンジ直前まで
- **弱い音**: 構成音のうち最大の16%未満を「○弦が弱い」と表示。押さえ方の図は聞こえている音ほど濃く光る
- **テスト音モード**: 合成音が自動演奏し、わざと遅れ、ミュート、押さえ間違いを混ぜる。マイクなしで採点の動きを確認できる
- **そのほか**: 進行のプリセットと自作、テンポ、1コードの拍数、練習時間、結果のコード別集計、記録と推移グラフ (localStorage: `uke.settings`, `uke.history`)、遅延の補正スライダーと「今回のズレの傾向で補正」
- コード表 `CHORDS` のフレット番号は 4弦→1弦 (G C E A) の順。High-G 前提

## 確認できたこと、できていないこと

- コード判定と弱い音のロジックは、Blackman窓のFFTをNodeで再現して16コード全部 (±20セントのチューニングずれ込み) で通ることを確認した
- 実マイクでの動作は未検証。オンセットのしきい値と音量ゲートは机上の値なので、実機で調整が必要
- claude.ai のアーティファクト画面ではマイク権限が渡されず使えなかった。`getUserMedia` は HTTPS か localhost が必要なので、`python3 -m http.server` か GitHub Pages で開く
- スマホは内蔵マイクとスピーカーが近く、クリック音が回り込みやすい。イヤホンを使うか、クリック音なしで画面の拍表示に合わせる

## わかっている制約

- タイミングの分解能は requestAnimationFrame 依存で約16ms。入出力の遅延は端末ごとに違う (Bluetoothは特に大きい)
- Low-G チューニングは未対応 (解析の下限が235Hz)
- テンポが速く1コードが1秒未満だと、集計フレームが少なく判定が不安定

## 次にやる候補

2. GitHub Pages に置く (外部依存は Google Fonts だけ。`index.html` にリネームすればそのまま動く)
3. 遅延の自動キャリブレーション (クリック音をマイクで拾って往復遅延を測る)
4. オンセット検出を AudioWorklet に移して分解能を上げる
5. PWA化、Low-G対応、コードの追加
