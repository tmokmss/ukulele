# 楽譜の JSON を書く

このリポジトリのアプリは、コード譜を JSON で受け取って「その曲を通して弾く練習」をする。
楽譜は **`songs/*.json` でリポジトリ管理**していて、画面ではタイトルから選ぶ。
書くのはほぼ Claude なので、**書いたら必ず検算してからコミットする**。

形式の一次情報は [docs/score-format.md](../../../docs/score-format.md)、
パーサは `src/core/score.ts`。食い違ったらコードが正しい。

## 手順

1. **コードを用意する**
   - 曲名だけ言われたら、**公開されているコード譜を1つ当たって照合してから書く**。
     記憶だけで書くと、それらしいのに曲と噛み合わない進行になる
     (きらきら星が実際そうで、12小節のうち6小節が外れていた)
   - 版が分かれる小節がある。どれを採ったかは控えておいて、最後に伝える
   - 裏が取れないときは、**そう言う。** 作り話の進行を渡すより、
     「この部分は自信がない」と添える方が役に立つ
   - コード譜を貼られたら、そこから小節だけ拾う。歌詞は要らない
   - **動画の URL を渡されたら** — コードが画面に出るタイプの練習動画なら、画面から起こせる。
     説明欄も字幕も当てにならない (字幕は日本語 ASR がコード名を壊す) ので、画面を読む。
     手順は [tools/chart-from-video/README.md](../../../tools/chart-from-video/README.md)。
     読み終えたら、小節数と BPM から出る演奏時間が動画の演奏区間と合うか見る。
     ここがずれていたら、どこかで小節を数え違えている
   - **倍テンポになっていないか、原曲の BPM を調べて確かめる。** 動画の 1 小節が
     原曲の半小節のことがあり、演奏時間が合っていても見抜けない。
     1 コードが 2 小節続くのが常態なら疑う (ポップスはたいてい 1 小節 1 コード)
   - **コード譜の横並びを、そのまま小節だと思わないこと。** 1 行に 8 個並んでいても、
     8 小節とは限らない。半小節ずつで 4 小節のことが多い。オー・シャンゼリゼが
     実際そうで、152 小節・5分04秒になっていた (実際の録音は 2分40秒)
2. **使えるコードに寄せる** (下の一覧にないコードは読み込めない)
3. **小節に割る** — 1小節 = 文字列1つ
4. **ストロークを決める** — 曲の雰囲気に合うものを `strum` に書く。分からなければ省略してよい
5. **`songs/` に置く** — ファイル名は半角の小文字とハイフン (`kirakira-boshi.json`)。
   ファイル名がそのまま id になり、画面に出る名前は JSON の `title`
6. **検算する**

   ```sh
   npm run score -- songs/<ファイル名>.json   # 書いたものだけ
   npm run score                              # songs/ 全部
   ```

   読めれば「何小節 / 何分 / コード / 1周何打 / コードも採点できるか」が出る。
   読めなければアプリと同じエラー文が出るので、それを見て直す。
   `npm test` にも「songs/ が全部読める」テストがある

   **出てきた「何分」を、実際の録音の長さと必ず突き合わせる。**
   `総小節数 × beatsPerBar × 60 ÷ BPM` が演奏時間なので、原曲の秒数とずれていたら
   小節の取り方を間違えている。**ちょうど 2 倍 (または半分) なら、ほぼ確実にそれ。**
   進行そのものが合っていても尺は合わないので、和音を見ているだけでは気づけない

   これが見るのは**形式だけで、和音が合っているかは見ない**。
   小節ごとにメロディを音名で書き出し、その区間の音がコードの構成音に収まっているかを
   自分で確かめる。収まらないなら、割り方かコードが違う
7. **渡す** — 置いた場所と、検算の結果、**照合したコード譜**を伝える。開発サーバーが
   動いていれば、画面の「楽譜」のコンボボックスにすぐ出る。
   GitHub Pages に出すにはコミットして push

## 形式

```json
{
  "title": "きらきら星",
  "keywords": ["kirakira boshi", "きらきらぼし", "Twinkle Twinkle Little Star"],
  "bpm": 90,
  "beatsPerBar": 4,
  "repeat": 1,
  "strum": "D-DU-UDU",
  "sections": [
    { "name": "A", "bars": ["C", "F C", "F C", "G7 C"] },
    { "name": "B", "bars": ["C G7", "C G7", "C G7", "C G7"] },
    { "name": "A'", "bars": ["C", "F C", "F C", "G7 C"] }
  ]
}
```

`keywords` には、アルファベットで引けるように**ヘボン式のローマ字**を必ず入れる
(`"kirakira boshi"`)。題名に漢字があれば**ひらがなの読み**、原題や英題があればそれも足す。
ファイル名も絞り込みに当たるので、ファイル名と同じ綴りだけなら省いてもいい。

短い曲は `sections` を省いて `"bars": ["C", "F", "G7", "C"]` だけでいい。

| 項目 | 既定 | 内容 |
|---|---|---|
| `bars` / `sections` | 必須 | どちらか一方 |
| `title` | 名前のない楽譜 | 曲名。記録にこの名前で残る |
| `keywords` | なし | 曲の一覧の絞り込みで当てる別名 (下記) |
| `bpm` | なし | 40〜180 に収まる値を書く。読み込むとテンポに入る |
| `beatsPerBar` | 4 | 拍子。3拍子なら 3 |
| `repeat` | 1 | 曲全体の繰り返し |
| `strum` | なし | ストローク。セクションごとに上書きできる |

### 小節の中

- `"C"` … その小節ぜんぶ C
- `"G7 C"` … 等分する (4拍なら2拍ずつ)
- `"."` … 直前のコードを伸ばす。`["C", "."]` で2小節、`"C . . F"` で3拍+1拍
- **割れるのは16分まで**。4拍の小節は 1 / 2 / 4 / 8 / 16 個にしか割れない。
  3個などにしたいときは `.` で位置を作る (`"C . Am"` は3拍子の3拍目でチェンジ)
- 食い込みは8分で書く: `"C - - - - F - -"` → F が3拍半から入る

### ストローク

文字数が**その小節の分割数**になる。8文字なら8分、16文字なら16分。

| 文字 | 意味 |
|---|---|
| `D` | ダウン |
| `U` | アップ |
| `x` | ミュート (チャッ) |
| `-` | 鳴らさない |

```
"D-DU-UDU"   8ビート (アイランドストローク)。迷ったらこれ
"DDDD"       4分で刻む。ゆっくりの曲、練習の入り口
"D-DU-UD-"   跳ねない8ビート
"DUDUDUDU"   細かく刻む。速い曲では書かない (下の制限)
```

**1小節に収まらないパターンは `|` で区切る。** 2つ以上並べると小節の頭から順に当たる。

```
"D-D--U-- | D--U--D-"   ボサノバ。1周が2小節
```

拍子 (`beatsPerBar`) を倍にして2小節を1小節に畳んではいけない。
クリックのアクセントが2小節に1回しか鳴らなくなり、拍が取れなくなる。

**コードチェンジの位置に打点があるか確かめる。** 1小節2コードの曲に
`"D-DU-UDU"` を当てると、3拍目 (2つ目のコードが入る位置) がちょうど休符で、
変わり目を鳴らせない。そういう曲は `"DDDD"` から始める。

## 制限 (ここを外すと読み込めない・採点できない)

1. **使えるコードは16個だけ**

   ```
   C  Am  F  G  G7  D  Dsus2  D7  Dm  Em  A  A7  E7  C7  Bb  Am7
   ```

   最新の一覧は `src/core/chords.ts` の `CHORDS`。
   足りないときは、
   - **移調する** — C / F / G / Am あたりのキーに寄せるとだいたい収まる
   - **カポを使う** — `"title": "曲名 (カポ2)"` のように題名に書いておく
   - **代理コードに寄せる** — `Cmaj7`→`C`、`Em7`→`Em`、`Asus4`→`A`。
     寄せたことは渡すときに一言添える

2. **コードが0.5秒より短いと、コード判定はされない** (リズムだけの採点になる)
   - 目安: 90BPM なら1拍 = 0.67秒なので、1拍ずつコードが変わってもぎりぎり判定できる。
     120BPM で1拍 (0.5秒) が限界、それより速く変わるとリズムだけ
   - 検算すると「リズムだけ採点」と出るので、意図していなければテンポか割り方を見直す

3. **16分のストロークを採点できるのは約135BPMまで**。それより速い曲に `"DUDUDUDU"`
   (16分) を書いても拾い切れない。8分にするか、`strum` を省く

4. 小節は400まで。`repeat` と `beatsPerBar` は 1〜16

## 例: 貼られたコード譜から作る

> ```
> Aメロ
> C        Am       F        G7
> C        Am       F    G7  C
> ```

```json
{
  "title": "○○",
  "bpm": 80,
  "strum": "D-DU-UDU",
  "sections": [
    { "name": "Aメロ", "bars": ["C", "Am", "F", "G7", "C", "Am", "F G7", "C"] }
  ]
}
```

1小節に2つ書いてある `F  G7` は `"F G7"` と並べて等分する。

## 渡すときに添えること

- 置いたファイルのパス
- 移調・カポ・代理コードで寄せた箇所
- 進行に自信がない箇所
- 検算の結果 (何小節・何分・コードも採点できるか)

## 直すとき

既にある楽譜を直す場合も同じ。`songs/` のファイルを編集して `npm run score` を通す。
**読めない楽譜は画面の一覧から消える** (エラー文は画面にも出る) ので、壊したまま放置しない。
